# RADIUS Manager — المرحلة الأولى (معمل خاص)

**الحالة:** مصدر تجريبي غير جاهز للإنتاج، بتاريخ 2026-11-23. لا تُدخل كروت المشتركين الحقيقيين ولا تنقل User Manager حاليا.

## ما الذي تم تنفيذه؟

- PostgreSQL في حاوية دون فتح منفذ قاعدة البيانات للخارج.
- خدمة FreeRADIUS 3.x من حزم Debian مع تهيئة SQL الرسمية ومنافذ RADIUS مقيدة على loopback افتراضيا.
- ASP.NET Core 10 Web API مع مصادقة مسؤول محلية، وصلاحيات أساسية وقيود عدد الطلبات.
- لوحة ويب عربية RTL محلية، إنشاء/تعديل باقات تجريبية محفوظة في PostgreSQL وإرسال إعداد **السرعة فقط** إلى `radgroupreply`.
- تهيئة أسرار آمنة عشوائية ونسخة `.env` محلية خارج git.
- اختبارات JavaScript و C# واختبارات تكامل قابلة للتشغيل في GitHub Actions.

## متطلبات التشغيل

- Debian/Ubuntu مع Docker Engine وDocker Compose plugin وPython 3.
- الوصول إلى الإنترنت *وقت بناء صور الحاويات فقط* لتحميل الصور والحزم؛ لا يحتاج المتصفح إلى CDN.
- منافذ 8080/TCP و1812/UDP و1813/UDP محلية على 127.0.0.1 افتراضيا.

## التشغيل

```bash
bash scripts/setup.sh
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

على **الجهاز نفسه** افتح `http://127.0.0.1:8080`.

على جهاز آخر داخل الشبكة افتح نفق SSH (من جهاز العميل):

```bash
ssh -L 8080:127.0.0.1:8080 USER@SERVER_LAN_IP
```

ثم افتح على جهاز العميل `http://127.0.0.1:8080`. استخدم اسم `admin`، واقرأ كلمة المرور من `ADMIN_PASSWORD` في ملف `.env` على الخادم. كلمة المرور لا تُرسل إلى أي موقع خارجي؛ لوحة الإدارة لا تعرضها أو تخزنها في LocalStorage.

## حدود الإصدار الأول

1. `quota_bytes` و `validity_days` **مخزنتان كمعلومات فقط وليستا مطبقتين على المصادقة**؛ لا تبيع باقات بهذا الإصدار.
2. لا يوجد إنشاء كروت الإنتاج أو التوزيع أو البيع أو نظام استخدام موحد بعد.
3. لا يوجد تفعيل لتزامن الجلسات أو خصم الرصيد أو فصل الجلسة عند نفاده.
4. ربط MikroTik والشبكات البعيدة عبر VPN سيكون في المرحلة التالية بعد الاختبارات.
5. HTTP Basic مقبول **للمختبر عبر localhost/SSH فقط**، وليس لواجهة مكشوفة على الإنترنت. قبل الإنتاج سنستخدم تسجيل دخول بجلسات آمنة وHTTPS وصلاحيات مفصلة.
6. في هذا النموذج تستخدم خدمة SQL حساب قاعدة بيانات واحدا بصلاحيات واسعة. يجب فصل صلاحيات التطبيق والمصادقة وإعداد نسخ احتياطية قبل الإنتاج.
7. خطة نشر نهائية وتحجيم المخزون والاختبارات لم تكتمل بعد.

## مفاهيم مهمة

- قيمة MikroTik `256k/1024k` تعني **رفع 256Kbps وتنزيل 1024Kbps**.
- لا تنفذ أي تعديلات على رواتر التشغيل الحالية. استخدم MikroTik اختبار معزولا.
- لا تفتح UDP 1812/1813 للعامة، بل استخدم VPN وربط CIDR محصور بالراوترات.
- عند تغيير `RADIUS_CLIENT_CIDR` بعد إعداد VPN أعد تشغيل خدمة radius، وتحكم في الجدار الناري بشكل مستقل.
- تشغيل النظام مستقلا عن الإنترنت يفترض أن يكون الراوتر والخادم متصلين على شبكة محلية متاحة.

## المرحلة الثانية — الكروت التجريبية (LAB ONLY)

- بعد تشغيل Docker، أنشئ باقة **بلا حد بيانات أو صلاحية** من اللوحة، ثم أنشئ كرتا تجريبيا منها.
- الكرت ينشأ باسم `lab_` عشوائي، وكلمة مرور مشفرة عشوائيا بطول 48 خانة؛ تظهر **مرة واحدة** عند الإنشاء.
- يمكن تجربة قبول الدخول عبر PAP/CHAP من داخل بيئة Docker، ورفض كلمة المرور الخاطئة، ثم تعطيل الكرت.
- ملاحظة أمنية: متطلبات PAP/CHAP في FreeRADIUS تستلزم تخزين سر قابل للاستخراج في جدول `radcheck` باسم `Cleartext-Password`، فلا تعتبره hash غير قابل للاسترداد. احم قاعدة البيانات ونسخها الاحتياطية.
- **لا تستخدم كروت الاختبار للبيع أو على شبكات إنتاج**: الرصيد والمدة والتزامن والـ CoA لم تُنفذ بعد. تعطيل الكرت يمنع المصادقة الجديدة لكنه لا يفصل جلسة موجودة.
- يدعم هذا الإصدار توليد كرت اختبار واحد في كل طلب، ولا يتضمن بعد طباعة دفعات أو استخداما موحدا عبر عدة راوترات.
- اختبر التكامل في المختبر: `bash scripts/lab-account-smoke.sh` بعد `bash scripts/setup.sh && docker compose up -d --build`.
- ترفع تغييرات المرحلة الثانية إلى PR مستقل، ولا تُدمج في `main` حتى اجتياز جميع الاختبارات.

## تحديث صورة PostgreSQL 16.16 للمختبر (بوابة أمان المرحلة 01)
- البناء الجديد يستخدم Alpine 3.24 بصورتها المثبتة بالبصمة، مع تصحيح libxml2، واستبدال gosu بأداة su-exec، ومزود ICU en-US. يعتمد على اختبارات الاستعادة السابقة، وليس ترقية ملفات قاعدة البيانات مباشرة.
- تحذير: لا يمكن تشغيل مجلد بيانات Debian القديم مباشرة على Alpine. حارس البدء يرفض مجلد البيانات القديم أو غير المعتمد قبل تشغيل entrypoint. لا تحذف volume ولا تستخدم down -v ولا تنشئ علامة الاعتماد يدويا. قبل أي نقل لبيانات موجودة، استخدم إصدار المصدر القديم للنسخ الاحتياطي المنطقي المشفر، ثم اختبر الاستعادة إلى cluster جديد منفصل وراجع ترتيب النصوص والبيانات والصلاحيات. لا يتم تغيير بيانات الإنتاج آليا.
- بناء الصورة محليا: docker compose up -d --build. فحوص CI تفحص معرفات الصور التي تشغل الخدمات فعليا. لا يزال اعتماد الإصدار مشروطا بنجاح فحص FreeRADIUS وبقية بوابات الأمان.
